# 시연

1. `http://localhost:5173/#impact`에서 변경 영향 분석을 연다.
2. 저장된 분석이 있는 대여 승인 요구사항을 Baseline으로 선택하고 조건/Revision을 확인한다.
3. 합성 변경 예제를 불러온다. 자산관리 담당자 권한은 새 제안이며 기존 정책 변경이 아니다.
4. 변경안 저장 → 영향 분석 시작. 긴 요청을 기다리는 대신 공유 Queue의 Job 상태를 조회한다.
5. 조건 좌우 비교, API/TC 후보, 신규 TC의 TEMPLATE_UNSUPPORTED, 실제 관계 및 Evidence를 검토한다.
6. 조건 유형/API 포함·제외/TC 분류를 조정하고 검토자·의견·상태를 입력하여 검토 결과를 저장한다. REVIEWED는 정책 승인과 다르다.
7. 저장 결과와 검토 이력을 재조회하고 변경 영향 Excel을 내려받는다. 7개 시트에 저장 데이터와 Graph 불완전 상태가 포함된다.

대표 실모델 검증 결과는 `real-e2e-results.json`, UI 검증은 `browser-results.json`을 확인한다. 저장된 대표 변경안을 다시 여는 것은 모델을 호출하지 않는다. `real-e2e.py`는 job-result.json이 있으면 기존 작업만 관찰하여 추가 모델 호출을 방지한다.

현재 워크벤치는 기존 TC 생성/승인/실행 버튼과 분리되어 있다. 사용자 검토 후 정책/근거를 확정하는 절차 자체는 별도 업무이며 이 기능이 정책을 자동 배포하지 않는다.
